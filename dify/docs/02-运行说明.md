# 02 · 运行说明

本文按「最快能玩上」到「完全本机、不用 Docker」两条路径写。任选一条即可。

---

## 1. 环境清单

| 组件 | 最低要求 | 本文验证版本 |
| --- | --- | --- |
| Docker（推荐） | 24+，compose v2 | Docker Desktop 4.x |
| Python（不用 Docker 时） | 3.11+ | 3.12.13 |
| Dify | 1.x | DSL 对齐 1.17.1 语义 |
| OceanBase seekdb | 1.3+ | 1.4.0.0 |
| PowerContext | 1.4.x | 1.4.1 |
| 对话模型 | 任意 OpenAI 兼容 / Dify 已接入的模型 | MiniMax-Text-01 |
| 内存 | 建议 ≥ 6 GB（seekdb 约 2 GB） | — |

端口占用：`2881`（seekdb）、`8000`（PowerContext）、`8088`（庭审后端）、`80`（Dify）。

---

## 2. 方式 A：Docker Compose 一键起依赖

在 `dify/` 目录执行：

```bash
docker compose -f deploy/docker-compose.yml up -d --build
```

这会启动三个容器：

| 容器 | 作用 | 端口 |
| --- | --- | --- |
| `absurd-court-seekdb` | 法典 / 判例 / 案卷 | 2881 |
| `absurd-court-powercontext` | 跨会话记忆 | 8000 |
| `absurd-court-api` | 庭审后端（自动建表 + 72 条法典） | 8088 |

等待约 20~60 秒（首次拉镜像 + 安装 PowerContext 依赖），然后：

```bash
curl http://127.0.0.1:8088/api/v1/health
```

预期（节选）：

```json
{
  "ok": true,
  "seekdb": { "ok": true, "statutes": 72, "precedents": 0 },
  "powercontext": { "ok": true, "url": "http://127.0.0.1:8000" }
}
```

> 如果 `seekdb.ok=false`：再等 30 秒（seekdb 首次初始化较慢），后端会自动重试 60 次。
> 如果 `powercontext.ok=false`：`docker compose -f deploy/docker-compose.yml logs powercontext` 看迁移日志。

## 3. 方式 B：本机运行（不用 Docker）

### 3.1 seekdb

任选其一：

**Docker（最省事）**

```bash
docker run -d --name absurd-court-seekdb \
  -p 2881:2881 \
  -v absurd-court-seekdb-data:/var/lib/oceanbase \
  oceanbase/seekdb:latest
```

**Windows MSI**

从 <https://mirrors.oceanbase.com/oceanbase/community/stable/windows/11/x86_64/> 下载 `seekdb-1.3.0.0-win64.msi` 安装，默认监听 `127.0.0.1:2881`，用户 `root`、空密码。

验证：

```bash
mysql -h 127.0.0.1 -P 2881 -u root -e "SELECT VERSION();"
```

期望输出包含 `OceanBase seekdb`。

### 3.2 PowerContext

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install "powercontext[cli,server]==1.4.1"

export POWERCONTEXT_HOME="$PWD/.powercontext"   # Windows: $env:POWERCONTEXT_HOME="$PWD\.powercontext"
export POWERCONTEXT_SERVER_HTTP_PORT=8000
export POWERCONTEXT_SERVER_ACCESS_MODE=disabled
powercontext server run
```

看到 `Uvicorn running on http://0.0.0.0:8000` 即可。默认使用 SQLite，不需要模型服务。

健康检查：

```bash
curl http://127.0.0.1:8000/health/live
# {"status":"ok"}
```

### 3.3 庭审后端

另开一个终端，在 `dify/backend/` 下：

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

export SEEKDB_HOST=127.0.0.1
export SEEKDB_PORT=2881
export SEEKDB_DATABASE=absurd_court
export POWERCONTEXT_BASE_URL=http://127.0.0.1:8000
export COURT_AUTO_INIT=1

uvicorn app.main:app --host 0.0.0.0 --port 8088
```

Windows PowerShell 对应写法：

```powershell
$env:SEEKDB_HOST="127.0.0.1"
$env:SEEKDB_PORT="2881"
$env:SEEKDB_DATABASE="absurd_court"
$env:POWERCONTEXT_BASE_URL="http://127.0.0.1:8000"
$env:COURT_AUTO_INIT="1"
uvicorn app.main:app --host 0.0.0.0 --port 8088
```

启动时会自动建库、建表、写入 72 条法典。也可以手动初始化：

```bash
python -m app.cli init --recreate   # 会清空判例/档案，重新写入法典
python -m app.cli check             # 打印法典条数与一次混合检索结果
```

## 4. 部署 Dify 并导入 DSL

### 4.1 启动 Dify

```bash
git clone https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
docker compose up -d
```

打开 `http://localhost`，完成管理员初始化。

### 4.2 让 Dify 容器访问到 `8088`

DSL 里两个 HTTP 节点默认写的是：

```
http://host.docker.internal:8088/api/v1/court/intake
http://host.docker.internal:8088/api/v1/court/commit
```

- **macOS / Windows Docker Desktop**：`host.docker.internal` 开箱可用，无需改；
- **Linux**：在 Dify 的 `docker/docker-compose.yaml` 里给 `api`、`worker` 两个服务加：

```yaml
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

然后 `docker compose up -d` 重建。

- **Dify 不在 Docker 里**：把地址改成 `http://127.0.0.1:8088`。

> 自检：进入 Dify 的 `api` 容器执行
> `docker compose exec api curl -s http://host.docker.internal:8088/api/v1/health`，
> 能返回 `"ok": true` 就说明网络通了。

### 4.3 导入

Dify 控制台 → **创建应用 → 导入 DSL 文件** → 选择 `dsl/absurd-court.chatflow.yml`。

导入后打开应用，做两处配置：

1. **③ 法官包大仁**：点击模型下拉框，选择一个你工作区可用的对话模型。
   - DSL 预设是 `minimax / MiniMax-Text-01`；Dify 1.x 的模型供应商以插件形式安装，若没有 MiniMax，先在「设置 → 模型供应商」安装并填 Key；
   - 换成 DeepSeek、Qwen、GPT、Claude 都可以，提示词不依赖特定模型；
   - 建议上下文 ≥ 8k，温度 0.8~1.0。
2. **①②⑤ 节点地址**：确认 `① 立案检索`、`⑤ 落库与量刑` 的 URL 正确（见 4.2）。

保存 → **发布** → 打开聊天窗口。

### 4.4 第一句话

```
我要起诉我的猫。它每天凌晨三点在我脸上蹦迪，还打翻我的水杯。
```

如果返回 502/超时：

- 在 Dify 的「工具 → 日志」里看 HTTP 节点状态码；
- 直接在宿主机 `curl http://127.0.0.1:8088/api/v1/health`；
- 常见原因是 Dify 容器访问不到宿主机 `8088`（见 4.2），或模型没有绑定。

## 5. 初始化、重置与停止

| 目的 | 命令 |
| --- | --- |
| 重新写入 72 条法典（保留判例） | `python -m app.cli seed` |
| 彻底重置 seekdb（清空判例/档案/案号） | `python -m app.cli init --recreate` |
| 重置 PowerContext 记忆 | 停止 PowerContext，删除 `POWERCONTEXT_HOME` 目录，重启 |
| 停止依赖栈 | `docker compose -f deploy/docker-compose.yml down` |
| 连数据一起删 | `docker compose -f deploy/docker-compose.yml down -v` |

> 重置 seekdb 后，玩家表被清空，下次开庭会为玩家创建新的 PowerContext Scope；
> 旧的 Scope 与记忆仍留在 PowerContext 中，只是不再被关联。想要完全干净，按上表同时重置 PowerContext。

## 6. 切换真实 Embedding（可选）

默认是零依赖的 128 维哈希向量（feature hashing），离线可用。想要语义召回更好，可以切到任意 OpenAI 兼容的 Embedding 服务：

```bash
export EMBEDDING_BACKEND=openai
export EMBEDDING_BASE_URL=https://api.openai.com/v1
export EMBEDDING_API_KEY=sk-REPLACE_ME
export EMBEDDING_MODEL=text-embedding-3-small
export EMBEDDING_DIM=1536

python -m app.cli init --recreate
```

注意：

- `EMBEDDING_DIM` 必须与模型实际维度一致；
- 切换维度后必须 `--recreate` 重建表与向量；
- 庭审后端启动时也会读这些环境变量，改完要重启后端；
- 失败时后端会直接报错，不会静默退回哈希（避免向量空间混用）。

## 7. 自检与复现命令

```bash
# 1) DSL 静态校验（节点/边/变量/Code 语法/凭据扫描）
python scripts/validate_dsl.py dsl/absurd-court.chatflow.yml

# 2) 按 Dify 节点顺序回放三幕（需要后端与 PowerContext 已启动，以及模型 Key）
export LLM_API_KEY=sk-REPLACE_ME
python scripts/run_demo.py --reset --out evidence

# 3) 抓取 seekdb / PowerContext 证据
python scripts/collect_evidence.py --out evidence
```

`run_demo.py` 默认走 MiniMax 的 OpenAI 兼容接口；换模型：

```bash
export LLM_PROVIDER=openai
export LLM_BASE_URL=https://api.deepseek.com/v1/chat/completions
export LLM_MODEL=deepseek-chat
export LLM_API_KEY=sk-REPLACE_ME
python scripts/run_demo.py --reset --out evidence
```

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `seekdb.ok=false`，`Unknown database` | 后端还没建库 | 等自动初始化，或 `python -m app.cli init` |
| `(2003, "Can't connect to MySQL server")` | seekdb 没起/端口不对 | `docker ps`，`mysql -h 127.0.0.1 -P 2881 -u root` |
| Dify HTTP 节点超时 | 容器访问不到宿主机 | 配 `host.docker.internal` 或 `extra_hosts`，见 4.2 |
| 模型节点报「模型不存在」 | 未绑定模型 | 在 LLM 节点重新选择模型 |
| 法官说「未检索到法条」 | seekdb 空表 | `python -m app.cli seed` |
| `powercontext.status = degraded` | PowerContext 没起 | 起 PowerContext；不影响开庭，只是失忆 |
| 记忆不跨会话 | 玩家 ID 变了 | 两次对话使用同一个 `player_id` 或同一个 Dify 用户 |
| 导入时提示 DSL 版本 | 0.1.5 导入 1.x 会自动迁移 | 确认导入即可，节点不会丢 |
| 刑期每次不一样 | 模型给的 `absurdity`/态度不同 | 属预期；后端只保证落在法定区间 |

## 9. 安全与凭据

- 仓库中不包含任何真实 API Key、密码或 Token；
- 模型 / Embedding 的 Key 只从环境变量读取，不写进 DSL、不写进日志；
- `evidence/` 中的请求记录已剔除 `Authorization` 头；
- PowerContext 默认 `ACCESS_MODE=disabled`，仅监听本机/内网；对外暴露时请开启其鉴权并限制 Scope；
- seekdb 默认 `root` 空密码，仅适合本地演示；生产部署请改密码并限制 2881 端口。
